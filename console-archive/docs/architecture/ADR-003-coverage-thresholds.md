# ADR-003: 覆盖率门槛锁定 90/85/80/88 且只增不减

- 状态：Accepted
- 日期：2026-10-05（爬坡冲刺后锁定；2026-10-16 深度档 + 热点清零后实测远超门槛）
- 决策者：质量架构师
- 关联：vitest.config.ts thresholds · S5 深度档 · R8 生产真阻断判例

## 背景 Context

2026-09 底覆盖率仅 45%；作为看盘系统，核心风险是**数据展示逻辑静默回归**（用户基于错误数据做决策）。需要门槛既真实防回归、又可达不虚假。

## 决策 Decision

vitest `coverage.thresholds` 锁定 lines 90 / functions 85 / branches 80 / statements 88——**略低于锁定日实测值留缓冲，但退化即 CI 阻断（exit≠0）**。门槛只增不减：提升需伴随测试增量，降低视为质量倒退。branches 是最紧维度（索引访问/兜底分支最多），任何大分支增量特性落地前先看余量。

## 备选方案 Alternatives

| 方案 | 优点 | 缺点 | 为何未选 |
|---|---|---|---|
| 无门槛 | 零维护成本 | 覆盖率随重构静默崩塌 | 违背看盘系统定位 |
| 100% 全覆盖 | 理论完备 | 大量不可构造防御臂（正则必选分组/取模恒界内）逼出假测试或 ignore 稀释 | S5 已实证 33+ 臂不可构造 |
| 70% 宽松 | 容易达标 | 防回归力弱 | 看盘数据正确性优先级高 |

## 后果 Consequences

- 正面：R8 实测 branches 78.3% **真阻断过一次**（不是摆设）；S2 双旗标新增 270 分支点时倒逼覆盖率抢救；当前实测 95.19/90.92/86.22/93.21 全线高于门槛。
- 负面：branches 余量曾仅 1 分支（贴线飞行），大特性前需补测；「可证死分支」需要逐条论证豁免（S5 33 处登记）。
- 中性：门槛数字本身五年内预计不动，实测值会持续爬升。

## 验证方式 Verification

`pnpm test:coverage`（thresholds 内建强制，COV_EXIT 即门禁）；guardrail-probe 探针 20（阈值抬 100 断言必拦，与生产阻断同机制）。

## 回滚路径 Rollback

下调 thresholds = 编辑 vitest.config.ts 一行——但被「只增不减」纪律与评审拦截；技术上可回滚，流程上视为倒退需附充分理由（如大规模删除低价值代码）。
