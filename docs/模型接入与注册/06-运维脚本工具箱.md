# 🧰 运维脚本工具箱

> **定位**：2026-10-05 全链治理日的脚本化收口——把当日所有手工运维动作固化为可重复执行的脚本闭环，覆盖**日常自检 / 灰度发布 / 事故恢复 / 看板重建 / 规则装载 / 节点扩容**六大场景。
> **原则**：以代码为准绳（每脚本均有生产实测输出）；密码经 SSH 读取不落盘；全部只读或幂等；bash 3.2 兼容（管理机 macOS）。

## 二、今日新增脚本（六大场景对应）

### 2.1 `scripts/health-full.sh` — 全链只读自检 ⭐ 日常入口

```bash
bash scripts/health-full.sh        # 全量七域
bash scripts/health-full.sh quick  # 核心六项
```

覆盖：公网入口 / NAS 网关 / Registry 就绪（ready≥4）/ **心跳 Token 认证活性**（无 token→401）/ dsv4 推理链 e2e / fluent-bit 双节点 / Loki / 告警三规则 / P0 指标露出（labelled Counter 未触发判 HELP 注册行）/ dsv4 容器 / Grafana 看板。**全部只读零中断**，凭据 SSH 现取。

**实测**（2026-10-05）：14 PASS / 3 FAIL → 3 项 FAIL 中 1 项为判据修正（rollback Counter 未触发属正常）、2 项暴露**真实生产事件**（dsv4 复崩 502/000）——自检脚本首跑即抓到事故，当场转入 recover 剧本。

### 2.2 `scripts/canary-manage.sh` — 灰度全生命周期

```bash
bash scripts/canary-manage.sh status   <model>                        # 查看灰度态
bash scripts/canary-manage.sh set      <model> <canary_id> <weight> [shadow]
bash scripts/canary-manage.sh promote  <model> <weight>               # 扩量
bash scripts/canary-manage.sh rollback <model>                        # 紧急回退 weight=0
bash scripts/canary-manage.sh finalize <model>                        # alias 正式切换 + DELETE
bash scripts/canary-manage.sh delete   <model>
```

**实测**：`set(weight=0) → status（五字段回读）→ delete` 干跑闭环全通。语义提醒：**alias = 客户端调用的 model 名**（非任意标签）。

### 2.3 `deploy/dgx/dsv4-recover.sh` — 旗舰诊断/恢复/取证/守护 剧本（五模式）

> 📘 **完整使用手册**：[07-dsv4-recover使用手册.md](07-dsv4-recover使用手册.md)（前置条件/五模式详解/健康判定语义/四场景剧本/FAQ）

```bash
bash deploy/dgx/dsv4-recover.sh                    # = check（安全默认）
bash deploy/dgx/dsv4-recover.sh check              # 只读诊断（判据：8001=200 + Registry state=ready）
bash deploy/dgx/dsv4-recover.sh recover            # 编排时序恢复（已健康自动跳过，FORCE=1 强制；完成后 e2e 推理验证）
bash deploy/dgx/dsv4-recover.sh rootcause          # 崩溃取证：生命周期轨迹/错误特征段/显存证据/Ray 集群/Registry 判定 + Loki 指引
bash deploy/dgx/dsv4-recover.sh logs [head|worker] [N]   # 快捷日志
bash deploy/dgx/dsv4-recover.sh watch [间隔秒=300]  # 守护循环：异常自动 recover（≤3 次熔断转人工）
```

**恢复时序**（TP2 跨机死锁的解法固化）：head 停 → worker 清态起 → head 起（GCS 就绪 50s）→ worker 对准 PG 注册窗口接入 → 每 60s 探测 8001+RestartCount（上限 15 轮）→ 就绪后等 Registry 转 ready。

**实测**：`check` 抓到真实复崩（8001=000/RC=8），当场执行 `recover`（详见 §四）。判据注：RestartCount 为容器生命周期累计（恢复操作也 +1），健康以 **8001=200 + Registry state=ready**（TTL 内心跳，服务端权威）为准。

### 2.4 `deploy/nas/load-prom-rule.sh` — 告警规则装载

```bash
bash deploy/nas/load-prom-rule.sh                          # prometheus-rules/ 全量
bash deploy/nas/load-prom-rule.sh <rules.yml>              # 单文件
```

固化链：scp → docker cp 进容器（conf 卷容器内只读，**禁容器内 sed**）→ prometheus.yml 追加**查重幂等** → busybox wget 热加载 → 规则组 API 实证。

**实测**：hotswap-gate 幂等重装 → `already-loaded + verified: yyc3-hotswap-gate`。

### 2.5 `deploy/dgx/setup-container-map.sh` + `deploy/dgx/deploy-container-map-remote.sh` — 节点部署双层

- 节点侧：`bash setup-container-map.sh`（幂等五步：文件校验/Loki 探测/timer/compose/映射注入+三重验证；NODE_ID 自动探测 hostname）
- 管理机批量：`bash deploy-container-map-remote.sh [节点...]`（默认 n1/n2；七件套同步 + 远程执行 + 汇总表，失败非零退出）

**实测**：n1（5 条映射）/n2（14 条）双绿。

### 2.6 `deploy/nas/import-grafana-dashboards.sh` — 看板导入

```bash
bash deploy/nas/import-grafana-dashboards.sh [看板.json ...]   # 默认 dgx-container-logs
```

Loki 数据源幂等补建（uid=loki）+ API 导入（overwrite=版本+1）。密码 SSH 现取不落盘；纯 shell 拼 JSON 零 python 依赖。

**实测**：`uid=yyc3-dgx-logs` 重导 → 回读 version=2 / panels=2。

## 五、运维教训沉淀（今日实战踩坑，已固化进脚本实现）

| # | 陷阱 | 正确做法（脚本内已固化） |
| --- | --- | --- |
| 1 | 手工 compose 漏 `--project-directory` → .env 不加载，PG/Redis 空密码崩溃环 | 网关重建一律 `rebuild-gateway.sh` |
| 2 | busybox wget 不支持 `-X POST` | `--post-data ""` |
| 3 | fluent-bit 镜像 distroless（无 sh/cat） | docker cp 反向拉取验证，禁容器内探查 |
| 4 | 管理 macOS bash 3.2 无 `declare -A` | 平行数组；`$VAR` 后勿紧跟全角标点（并入变量名 → unbound） |
| 5 | `pkill -f` 匹配自身命令行 → 断自家 SSH | `pgrep -f "^锚定模式"` 后 kill |
| 6 | NAS 非交互 SSH 无 PATH（docker/ls/sleep 全裸） | 远端一律 `bash -lc`；命令串本地展开参数 |
| 7 | NAS ACL 拒容器内用户读 bind-mount 单文件 | docker cp 注入 / `user: "0"` 权衡 |
| 8 | docker cp 后 mv 换 inode 破坏单文件 bind mount | 注入类一律 docker cp，不用宿主 bind |
| 9 | labelled Counter 未触发时无 series | 健康判据用 `# HELP` 注册行，非 sample 行 |
| 10 | daocloud 部分镜像拉取停滞 | 备源 `docker.1ms.run`（fluent-bit 实证） |
