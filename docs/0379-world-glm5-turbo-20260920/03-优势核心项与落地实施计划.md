## 一、七项目优势核心项总目录（合并审计结论）

### 1.1 litellm（1.8G，Python）—— 请求生命周期工程化

| # | 核心项 | 机制（源码实读 [ARCHITECTURE.md](file:///Users/yanyu/YYC3-GitHub/GitHub-API/litellm/ARCHITECTURE.md)） | 落点 |
| - | ------ | -------- | ---- |
| L1 | 双层缓存鉴权 | DualCache 内存→Redis→PG 逐级 miss，热路径 0 DB 查询 | auth.py 校验链 |
| L2 | 成本计算器 | `completion_cost(tokens×price)` → `_hidden_params` → `x-litellm-response-cost` 头 | 虚拟密钥计费内核 |
| L3 | 异步记账管道 | spend 入 Redis 队列 → 后台协程批量写 PG，**DB 写不进请求路径** | spend_logs 管道 |
| L4 | ProviderConfig 转换层 | 每供应商一对 `transform_request/transform_response` 纯函数 | 云适配器标准化 |
| — | 许可注意 | MIT 但 **enterprise/ 目录排除**，复用时显式规避 | 模式重写即可规避 |

### 1.2 one-api（20M，Go）—— 渠道治理运营层

| # | 核心项 | 机制（源码定位 relay/adaptor/interface.go、monitor/channel.go） | 落点 |
| - | ------ | -------- | ---- |
| O1 | Adaptor 8 方法契约 | Init/GetRequestURL/SetupHeader/ConvertRequest/DoRequest/DoResponse/GetModelList/GetChannelName，50+ 厂商已验证 | providers/ 目录契约设计参照 |
| O2 | 渠道熔断+自愈+告警 | 成功率低于阈值自动禁用+邮件通知，恢复自动启用——**自愈闭环** | probe_all() 验活+Grafana 告警 |
| O3 | 分组×模型二维调度 | `CacheGetRandomSatisfiedChannel(userGroup, model)`，倍率分级计费 | 虚拟密钥 model_whitelist+倍率 |
| O4 | 多 Key 轮询 | 渠道内多 Key 计数轮换，失败跳下一把 | upstream api_key_envs |
