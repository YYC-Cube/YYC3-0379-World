## 五、后续建议（P1/P2）

### [P1] 建议尽快

1. **pytest 运行时长 7m28s 偏长**：52 用例中含真实网络/模型调用的用例拖慢全量。建议拆分 `pytest -m "not integration"` 快速回归层与 nightly 全量层，CI 五段流水线按标记分发
   → ✅ **已落地（v9, 2026-09-23）**：pytest.ini 默认快速层（34 用例 1.58s，提速 280×）；Makefile test-fast / test-integration / test 三目标；CI 分层分发（PR 快速层 / main 全量）
2. **coverage 55% 距离团队 80% 基线有缺口**：优先补 `core/api/services/` 各云适配器的错误分支覆盖（尤其 `_ensure_key` 401 路径已测，但流式入口错误分支薄）
   → 🔄 **部分落地（v9）**：三云适配器 + ollama 主链路已补齐 15 用例（deepseek 24→87% / openai 27→83% / ollama 53→84% / zhipu 13→86% / key_guard 30→100%）；剩余缺口在 mcp_client/mcp_integration/virtual_key_manager/document_processor（0-21%）等非网关核心面，建议按模块优先级分批推进
3. **`core/scripts/` 目录残留盘点**：本轮仅处置确认零引用的 1 个文件；建议后续专项盘点该目录，避免「lint 清理版覆盖文档版」这类双源再生
   → ✅ **已落地（v10, 2026-09-23）**：21 文件三类处置——删 5（cogagent_chat / cogvideox_generator / deploy-cogvideox / test-local-models / update-model-configs.sql，旧本地模型路线零引用残留）+ 变量清单 Cog 环境变量 6 行同步清理；保留标注 3（文档引用中）；保留 13（运维在用）

### [P2] 建议规划

1. **版本发布自动化**：当前 CHANGELOG 定版依赖人工。建议在 CI 中加 release job：tag 推送 → CHANGELOG Unreleased 段自动定版 + README 徽章同步替换
   → ✅ **已落地（v10, 2026-09-23，方案微调）**：CI release job 采用「门禁校验」而非「自动改写」（防 CI 静默改文档引入不可审计变更）：tag 推送 → 三方一致性门禁（tag ↔ CHANGELOG 定版段 ↔ README 徽章）→ ReleaseNotes 从定版段自动提取 → GitHub Release（tag 含 `-` 自动 prerelease）。定版动作保留人工提交，CI 负责红线拦截。落地当日即抓到 v9 提交的徽章版本漂移，门禁价值自证
2. **文档失效检测**：本轮幽灵引用两组的共性根因是「先改文档后放弃文档，但索引/日志先入库」。建议加 docs linkchecker（如 lychee/markdown-link-check）进 CI 第四段，链接失效即红
3. **ADMIN_API_KEYS 生产落地**：.env.example 已补模板；生产 .env 需真实分离管理面密钥并轮换，配合 `/v1/admin/**` 的 403 实测验证一次
