# svl2 A 类任务格式缺陷 · 定位与修复（U16 移交 · 网关线回执 2026-11-01 · **实测终版**）

> **实测结论（TL;DR）**: 层属=**模型侧**（直连同参 A 0/5 比网关 1/5 更糟，aify 洗清）；主形态=**多文档输出**（紧凑原文+pretty 副本，9/10；尾巴`}` 1/10）；**JSON 提取器修复后 15/15**（agent4b 基线平齐，p50 1.2s vs 2.2s）

## 一、缺陷定位（静态取证 · 修正 OPS 定性两处）

### 1.1 五例逐条形态（svl2 A 电池）

| 例 | tok | 形态 | 原文特征 | 判分器行为 |
|---|---|---|---|---|
| A#1 | 142 | **重复副本 ×2**：紧凑 JSON + 同语义 **pretty-print 副本** | 两份均完整合法，内容一致（1 scene） | 首`{`→尾`}` 跨两文档 → `}{` 接缝解析炸 → fail |
| A#2 | 269 | **碎片化多文档 ×4**（⚠ 修正：OPS 记「同一 JSON 2~4 份」，实为**每 scene 一个独立 JSON 文档**，四份内容各不相同） | 4 × `{"scenes":[单scene]}`，空行分隔 | 同上跨文档 → fail |
| A#3 | 124 | 尾部多 `}`（`]}}`） | 单文档，多闭合一层 | `Extra data` → fail |
| A#4 | 69 | ✅ 干净单文档 | 唯一通过（got=1） | pass |
| A#5 | 80 | 尾部多 `}`（response_format json_object 不救，OPS 复测） | 同 A#3 | fail |

### 1.2 三个判定结论

1. **长度梯度（核心签名）**：<70 tok 干净（A#4 + B/C 全部 12–40 tok）→ 80–130 tok 尾巴 `}` → 140+ tok 副本/碎片。**长度相关、能力无关**（画面描述质量本身不差——OPS 定性维持：格式层缺陷非能力缺陷）。
2. **网关流式重组假设已由直连电池定案洗清**（原为降权推断，§4.1 ③ 实证）：aify `/v1` 为**非流式**透传（OPS-LOG 10-31 01:4x），且 A#1 第二副本是**重新排版**（pretty-print）而非逐字重复——流式重组损伤应产生逐字重复或乱序，不会重排版；**直连同参（思考关）A 0/5 比网关更糟**。**层属定案：模型侧长结构化输出行为**。旁证：DGX 上 mamba 系「长输出静默结构退化」已有两案先例（q38 `!!!!` 乱码 · MF-NIM token0 连发，不同引擎不同模型但同族签名，见 OPS-LOG 10-31 双案 issue 草稿）。
3. **判分器放大器效应**：eval4 `extract_json` 取「首 `{` 至尾 `}`」子串——对多文档形态必然击穿；尾部 `}` 亦然。判分语义（必须解析出合法 JSON）正确，但**修复层（提取器）可确定性兜底全部三种形态**（见 §三）。

## 三、修复 ③ · 提取器（参考实现 + 逐样本推演 + aify patch）

### 3.1 算法（`scripts/svl2_json_rescue.py` 为可执行参考实现，内嵌 5 坏样本自测）

1. 剥 markdown 围栏（沿用 eval4 口径）；
2. `JSONDecoder.raw_decode` 从首个 `{` 起逐个提取**完整顶层对象**，天然忽略尾部垃圾（`]}}` 的多余 `}`）；
3. 多文档合并规则（保守）：仅当所有文档 **键集完全一致且目标键均为数组** 时合并数组并按内容哈希去重（A#1 重复副本 → 去重取一；A#2 碎片 → 合成 4-scene 数组）；否则只取首份；
4. 单文档原样返回（**对现有合法输出零扰动**）。

### 3.2 逐样本推演表（手工验证，运行时由自测脚本复核）

| 样本 | 提取器输入 | 输出 | 判分（eval4 口径） |
|---|---|---|---|
| A#1 | 紧凑+pretty 两份（同 1 scene） | `{scenes:[s1]}`（去重） | ✅ pass（got=1） |
| A#2 | 4 份单 scene 文档 | `{scenes:[s1..s4]}`（合并） | ✅ pass（got=4，优于 a4b 的 1） |
| A#3 | `...}]}}` | 首 raw_decode 值，尾 `}` 丢弃 | ✅ pass（got=2，idx3 需≥2） |
| A#5 | `...}]}}` | 同上 | ✅ pass（got=1） |
| A#4 / B×5 / C×5 | 单文档 | 原样 | ✅ 维持原判（零回归） |

**预期：svl2 15/15（格式层）；质量层（scene 数/文案）另列不改判。**

### 3.3 aify 网关 patch（yyc3-33 `/opt/yyc3/aify/services/llm-gateway.js`，scp→Edit→scp 通道，留底先行）

```js
// openAICompatChat() 返回 content 前插入（opt-in 灰度：env LOCAL_DGX_JSON_RESCUE=on
// 或请求头 x-llm-json: rescue 才启用——不影响既有消费者与 TS 家臣线自有 extractStepJson）
function jsonRescue(s) {                       // ← 与 svl2_json_rescue.py 同算法
  if (!s || typeof s !== "string") return s;
  let t = s.trim();
  if (t.startsWith("```")) t = t.split("\n").slice(1).join("\n").split("```")[0];
  const docs = []; let i = 0;
  while (i < t.length) {
    while (i < t.length && /\s/.test(t[i])) i++;
    if (i >= t.length || t[i] !== "{") break;
    try { const [obj, end] = JSON.rawDecodeAt(t, i); docs.push(obj); i = end; }
    catch { break; }                            // JS 无内建 raw_decode：见下方实现注
  }
  if (docs.length <= 1) return docs[0] !== undefined ? JSON.stringify(docs[0]) : s;
  const keys = Object.keys(docs[0]).sort().join(",");
  if (!docs.every(d => Object.keys(d).sort().join(",") === keys)) return JSON.stringify(docs[0]);
  const out = {};
  for (const k of Object.keys(docs[0])) {
    const vals = docs.map(d => d[k]);
    if (vals.every(Array.isArray)) {
      const seen = new Set(); const merged = [];
      for (const arr of vals) for (const item of arr) {
        const h = JSON.stringify(item);
        if (!seen.has(h)) { seen.add(h); merged.push(item); }
      }
      out[k] = merged;
    } else out[k] = vals[0];
  }
  return JSON.stringify(out);
}
// 实现注：JS 标准无 raw_decode，用「逐字符括号深度扫描 + JSON.parse 切片」实现
// rawDecodeAt(str,i)：从 i 起找平衡的 {...} 跨度（处理字符串内引号转义），切片 JSON.parse；
// 失败则 throw。完整可运行实现见 scripts/svl2_json_rescue.py 附带的 JS 移植版函数体。
```

部署顺序：留底 `llm-gateway.bak-20261101-jsonrescue` → 打补丁 → `node --check` → pm2 restart → E-0 实验 ③ 复验 → 15 例重放。回滚 = 恢复留底。

### 4.2 形态分布实测（A 类 10 失败例）

- **多文档 = 9/10 主形态**：`{"scenes":[…]}` 紧凑原文 + `\n\n` + **pretty-print 副本**；网关 A#1 实测**循环 ×16 份直至 1024 硬顶截断**（finish=length）——多文档膨胀时网关 `LOCAL_DGX_MAX_TOKENS=1024` 硬顶会放大损伤（截断中段时仅首份完整，提取器仍可救）。
- 尾巴 `}` = 1/10。
- **逐例随机、形态稳定**：本轮 A#5 过/A#4 挂，与归档（A#4 过/A#5 挂）相反——temperature=0 下仍不稳定，符合有状态引擎（mamba/radix）flaky 签名，与 q38 `!!!!`、MF-NIM token0 两案同族（OPS-LOG 10-31 双案 issue 草稿可并案参考）。
- 直连首跑思考污染教训已固化进驱动器（`--think off` 默认与网关同参；A 类 775-2030 tok/65-80s 口径作废）。
