## 二、双 DGX Spark 节点资源拓扑与部署规划

基于 2 台 DGX Spark GB10（单台 128GB 统一内存，200Gbps RoCE 直连），采用**「核心推理分布式 + 支撑能力单节点」**的混合部署架构，实现资源利用率最大化与低延迟保障。

### 2.1 节点分工总览

| 节点角色 | 核心定位 | 部署模型与组件 | 内存占用估算 | 核心优势 |
| --- | --- | --- | --- | --- |
| 节点 1（推理主节点） | 核心算力池，大模型分布式分片 + 中模型推理 + 检索核心 | 1. 元启天枢基座模型（TP 分片 1/2）   2. 语枢万物 / 预见先知共享模型   3. nemotron-3-embed-1b 嵌入模型   4. llama-nemotron-rerank-1b-v2 重排模型   5. Milvus 查询引擎 | ~110GB / 128GB | 大模型张量分片本地计算，减少跨机通信；嵌入与重排紧邻向量库，检索链路延迟最低 |
| 节点 2（能力支撑节点） | 安全 / 解析 / 轻量 Agent + 存储编排 + 监控 | 1. 元启天枢基座模型（TP 分片 2/2）   2. 智云守护全套安全模型   3. 言启千行、知遇伯乐轻量模型   4. 创想灵韵、格物宗师专用模型   5. nemotron-ocr-v2 文档解析   6. Milvus 数据节点 + 编排引擎 + 监控 | ~105GB / 128GB | 非核心推理任务全部卸载，避免抢占主模型算力；OCR、安全等批量任务独立运行，不影响用户交互延迟 |

### 2.2 分布式通信架构

1. **大模型张量并行**：元启天枢基座模型采用 TP=2 张量并行，通过 200Gbps RoCE v2 直连，开启 GPUDirect RDMA，NCCL 2.29+ 优化通信，跨机张量传输延迟 <2μs。
2. **Agent 间通信**：采用 A2A 协议，通过节点 2 的编排引擎中转，基于 gRPC + 消息队列解耦，支持异步任务调度与状态同步。
3. **知识库访问**：节点 1 推理模型通过 RoCE 高速访问节点 2 的向量数据库，单查询延迟 <10ms。

### 2.3 高可用架构设计（对齐「五高-高可用」）

- **主模型冗余**：nemotron-3-super-120b 在双节点各部署一份独立实例，作为元启天枢的降级备份；主模型故障时 10 秒内切换至备份模型，保障核心调度能力。
- **关键组件双活**：安全模型、嵌入模型、OCR 模型在双节点均部署实例，通过负载均衡调度，单节点故障不影响链路。
- **会话持久化**：对话上下文、Agent 状态双节点同步存储，支持故障无缝切换，故障转移时间 <5 秒。

### 3.2 三大核心闭环机制

1. **知识检索闭环**：所有 Agent 执行任务时，均可调用公共 RAG 链路；检索结果自动携带来源标识，格物宗师校验时可溯源原文，从机制上解决幻觉问题。
2. **工具调用闭环**：预见先知、语枢万物可通过 MCP 协议调用代码执行环境、企业数据库、第三方 API；执行结果返回 LLM 进行二次解读，形成「推理-行动-观察」的 ReAct 完整闭环。
3. **治理审计闭环**：全链路每一步均生成审计日志，智云守护全程监控异常行为；红队测试用例定期注入验证，安全规则持续迭代，对齐架构伦理治理要求。

### 4.3 Agent 编排层集成配置

1. **框架选型**：采用 LangChain + AutoGen 作为 Agent 编排框架，通过标准 OpenAI 兼容接口调用所有 NIM 模型服务，实现模型层与编排层完全解耦。
2. **协议适配**：内置 MCP 协议服务端，对接企业内部 ERP、CRM、代码仓库、监控系统等工具，所有 Agent 可统一调用，无需重复适配。
3. **状态管理**：采用 Redis + SQLite 双存储实现会话状态、Agent 上下文持久化，支持断点续办与多端同步。

# 新增存储/终端硬件融合补充方案（原双DGX Spark架构扩展）

## 硬件资产汇总

1. 算力核心：2台 DGX Spark GB10（200Gbps RoCE直连，每台128GB统一内存）
2. 存储集群：NAS，内存32G，RAID1（核心数据镜像）+ RAID6（大容量知识库/模型缓存）
3. 本地工作站：MacMAX，128G内存、4T本地高速磁盘
4. 软件底座：NVIDIA NIM模型库 + AI FAmily 拟人Agent协同架构

## 一、硬件分层职能划分（打通算力-存储-本地开发全链路）

### 1. 分层定位

1. **算力层：双DG Spark（生产推理/分布式模型TP=2）**
    承载元启天枢大基座、数据分析、多Agent并行推理、RAG向量计算，全部NIM容器分布式服务。
2. **中心存储层：NAS 32G（RAID1+RAID6混合阵列）**
    - RAID1：高可靠核心数据（API密钥、审计日志、Agent提示词模板、企业涉密知识库、模型配置文件、安全审计记录）双副本容灾，绝不丢失；
    - RAID6：大容量冷/温数据池（完整NIM模型镜像库、全量企业知识库原始文档、OCR扫描素材、历史对话快照、训练微调数据集、视频仿真素材）；
    - NAS 32G内存用作文件缓存、Milvus向量库冷存储缓存、OCR批量任务缓冲池。
3. **本地开发调试层：MacMAX 128G / 4T本地盘**
    开发、提示词工程、Agent流程调试、小模型本地验证、知识库预处理、数据集清洗、本地向量测试、离线原型；4T本地高速盘存放测试模型、本地开发数据集、调试日志。

### 2. 三层高速互通链路

1. DGX ↔ NAS：万兆以太网链路，模型拉取、知识库批量入库、训练数据集读写；
2. MacMAX ↔ NAS：2.5G高速内网，开发完成的提示词/数据集/测试模型同步至NAS统一存储；
3. MacMAX ↔ DGX：SSH+内网高速通道，远程调用双机NIM服务，本地调试Agent工作流。

## 二、NAS存储精细化资源分配（RAID1 / RAID6分区规划）

### 1. RAID1（高可靠分区，双盘镜像）容量&用途

| 分区用途 | 存储内容 | 对接服务 |
| -------- | -------- | -------- |
| Agent核心配置库 | 全套AI FAmily提示词模板、各角色系统Prompt、ReAct-C工作流配置、双机docker-compose、NIM启动参数 | MacMAX开发同步、DGX服务启动加载 |
| 安全审计日志库 | 智云守护全链路审计、PII脱敏记录、越狱攻击检测日志、红队测试报告 | 双DGX日志持久化，合规审计溯源 |
| 企业核心知识库（热库） | 高频访问代码库、经营文档、政策文件（RAG每日高频检索素材） | 双DGX Milvus向量库定时同步更新 |
| 密钥&权限库 | NIM API Key、A2A Agent通信密钥、RBAC权限配置、数据库账号 | 只读挂载，仅算力节点授权访问 |

### 2. RAID6（大容量容错分区，多盘冗余）

1. NIM完整模型仓库
    全量138款NIM模型镜像持久化存储，双DGX启动时从NAS预拉取缓存至本地SSD，避免重复下载；支持DeepSeek、GLM、Nemotron全系列MoE大模型离线部署，断网可生产。
2. 原始知识库冷存储
    海量PDF、扫描图纸、代码工程、视频素材、PCB工业图、生物序列原始文件；Nemotron-OCR批量任务源文件池，每日定时批量解析入库至向量库。
3. 数据集与微调资源
    代码微调数据集、经营预测时序数据集、Agent反馈迭代样本，格物宗师质量训练素材，支持后续LoRA微调任务数据集读取。
4. 历史业务快照
    月度经营报告、历史对话记录、预测结果存档，供预见先知做长期趋势复盘。

### 3. NAS 32G内存调度策略

- 16G：文件系统读写缓存（模型、文档高速读取，降低DGX拉取延迟）
- 10G：Milvus冷数据缓存（RAID6冷知识库向量分片缓冲）
- 6G：OCR批量任务内存缓冲（批量文档预处理峰值负载）

## 三、MacMAX 128G/4T本地开发环境落地适配

### 1. 硬件能力适配场景

128G大内存可独立跑中小NIM模型做本地验证，无需占用双DGX生产算力，实现**开发/生产环境隔离**，避免调试抢占业务并发资源。

#### MacMAX本地可运行模型清单（原型调试专用）

- 嵌入系列：nemotron-3-embed-1b、llama-nemotron-rerank（本地RAG原型）
- 轻量Agent基座：nemotron-mini-4b、laguna-xs-2.1（代码调试）
- 安全组件：nemoguard、gliner-pii（提示词注入本地红队测试）
- OCR轻量版：nemotron-ocr-v1（文档预处理调试）
- 创意小模型：inkling多模态轻量实例

### 2. 4T本地磁盘分区规划

1. 开发工作区（1.5T）：提示词工程文档、AI FAmily架构脚本、Agent编排代码、测试用例库；
2. 本地模型缓存（1.5T）：调试用轻量化NIM模型，无需每次从NAS拉取；
3. 预处理数据集（1T）：本地清洗代码/业务文档，清洗完成同步至NAS RAID6统一存储。

### 3. 开发→生产流水线（MacMAX ↔ NAS ↔ DGX闭环）

1. Mac本地完成提示词优化、Agent流程调试、数据集清洗；
2. 校验无误后，自动同步脚本推送至NAS RAID1配置分区；
3. 双DGX每日定时从NAS拉取最新Prompt/知识库更新，热重载NIM服务；
4 调试失败、测试样本留存Mac本地，不污染NAS生产存储。

## 四、全链路数据流转闭环（新增存储/终端融合完整版）

### 1 知识库入库完整链路

MacMAX本地清洗文档 → 同步NAS RAID6原始素材池 → 双DGX定时拉取 → nemotron-ocr-v2结构化解析 → nemotron-3-embed向量化 → Milvus向量库（DGX内存热缓存，NAS RAID6持久向量分片）

### 2 Agent配置迭代链路

MacMAX编写/更新元启天枢、智云守护等角色提示词 → 同步NAS RAID1配置库 → DGX服务热加载更新Prompt，无需重启容器

### 3 模型部署链路

NAS RAID6存储完整NIM模型镜像 → DGX启动时预缓存至本地高速盘 → TP=2分布式推理；Mac本地仅同步轻量模型用于离线调试

### 4 日志&合规存储链路

双DGX全链路审计日志实时写入NAS RAID1镜像分区，永久双副本留存，满足等保审计要求

### 5 离线本地调试链路

MacMAX加载本地小模型，复现业务问题；调试方案确认后同步至NAS，更新生产环境配置

## 五、资源负载隔离优化（避免存储抢占算力）

1. NAS批量OCR/数据集任务**禁止直连DGX**：全部先在MacMAX完成预处理，仅结构化文本同步至算力节点，消除NAS大文件读写抢占RoCE通信带宽；
2. 双DGX仅挂载NAS只读模型/知识库目录，写入操作统一限制NAS侧，算力节点不做大量磁盘写入，释放统一内存用于KV缓存；
3. MacMAX开发流量与生产业务网络VLAN隔离，本地测试不会占用DGX 200Gbps高速互联带宽；
4. NAS RAID6大容量模型库设置带宽限速，夜间闲时同步模型至DGX本地缓存，白天业务高峰不占用内网IO。

## 六、扩容与容灾补充

1. 容灾：核心配置、热知识库RAID1双副本，NAS硬件故障不丢失Agent调度核心数据；
2. 扩展：后续新增DGX节点，仅需从NAS统一拉取模型与配置，无需单独分发文件；
3. 成本分流：大量原始文档、历史冷数据下放NAS存储，不占用DGX昂贵高速本地磁盘；
4. 研发解耦：MacMAX承担全部测试、预处理工作，双DGX100%资源留给线上用户问答、智能体生产业务。

## 七、配套补充部署修改点（原docker-compose更新）

1. 所有NIM容器增加NAS远程挂载配置（只读：模型、知识库；日志目录远端写入NAS RAID1）；
2. 新增MacMAX同步脚本（rsync自动推送配置/数据集至NAS定时任务）；
3. Milvus存储分层：热向量存DGX内存，冷分片自动下沉NAS RAID6；
4. 新增NAS内存缓存调度参数，OCR批量服务限定NAS内存使用上限。
