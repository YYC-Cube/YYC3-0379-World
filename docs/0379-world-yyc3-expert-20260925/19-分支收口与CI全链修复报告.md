## 三、CI 完善清单（防复发）

1. **门禁工具 pin 版本**（`ac0d163`）：black==26.5.1 / flake8==7.4.1 / isort==9.0.2 / import-linter==2.15 / pytest==9.0.3 / pytest-cov==7.1.0 / respx==0.23.1——上游规则漂移升级须本地验证后显式变更；
2. **dependabot ignore numpy>=2.5**：与基础镜像 Python 版本强耦合的依赖，升级须同一显式变更执行；
3. **lint 口径指向实体目录 `core/api`**（`6e89449` 前置修正）：`core/app` 是符号链接，Linux 解链二次扫描致 isort 误报；
4. **isort 判定配置化**：pyproject.toml `[tool.isort] known_first_party=["app"]`；
5. **integration 建表三段式**（`ea4f039`）：角色+扩展预启用 → ORM 基础表（经 conftest 注册，非裸 sys.path——app 包是 importlib 手工映射）→ init SQL 幂等增量；PG 镜像必须用 pgvector 变体；
6. **鉴权默认开启**：test job 不设 `AUTH_ENABLED`——RBAC 用例依赖鉴权，用例自带 key header；
7. **测试专用依赖显式声明**：sqlite 内存库 fixture 的 aiosqlite 等只在 CI 工具链行声明（本地 .venv 的历史安装会掩盖缺位——L9 教训：本地验证前先 `pip freeze` 对齐 CI 安装面）；
8. **【待办】分支保护**：本轮 dependabot 又自动落 main 16 提交（含 actions 大版本 bump），required checks 缺失是反复救火的根源（P3，需 admin）。

### 五.2 deploy 冒烟 401 诊断（历史遗留，非本轮引入）

**现象**（run 37241237056）：「旗舰公网冒烟」步骤第一步 `/v1/models` 解析即挂 `TypeError: string indices must be integers, not 'str'`（0.7s 即返回）；而前序「公网健康验证」步骤已通过（NAS 网关存活）。

**根因定位**（本地复现）：无 key 直连生产 `/v1/models` 实测返回 HTTP 401 + 响应体 `{"error":"Unauthorized","message":"Missing authentication credentials","detail":"Please provide either a valid JWT token or API key"}`。冒烟脚本 `for m in json.load(sys.stdin)` 迭代该 dict 得到的是 **key 字符串**，`m['id']` 即报 string indices——与 CI 报错精确吻合 → **CI 的 `PROD_API_KEY` 已失效**（疑 9-26 网关密钥轮换后 GitHub secret 未同步）。

**双因素结论**：

| 因素 | 性质 | 修复路径 |
| --- | --- | --- |
| ① `PROD_API_KEY` secret 失效 | 主因，用户侧可修 | GitHub repo secrets 同步生产 key |
| ② 旗舰 `dsv4` 停摆 | 叠加因素，待用户决策 | A/B/C 预案（建议 A：退役 N2 8B rerank） |

即使 key 同步，模型列表断言仍会因旗舰缺位而失败——两因素需先后落地方可全绿。

**历史佐证**：main 近 100 个 run 无一 success——deploy 冒烟从未实证绿过，属历史遗留非本轮引入。

**修复建议**：① 用户在 GitHub repo secrets 同步 `PROD_API_KEY`；② 落实旗舰 A 预案恢复上游；③ 冒烟脚本加容错（非 200 时显式报「认证失败/上游不可达」而非裸 TypeError）。
