### 2026-09-25 Phase 5 - 门禁验证与缺陷修复（本会话）

**操作类型**: Bug修复 + 配置变更
**验证结果**: 详见下方门禁记录

#### 修复 1：Mock 回显 "UNSAFE" 字样导致全链路误拦截

- 现象：基线 `14 failed, 30 passed`，失败集中于九步编排全链路 blocked
- 根因：Mock 模式 `_mock_run` 回显提示词原文（含「只回答 SAFE 或 UNSAFE」字面量），
  合规判定用裸 `in` 匹配 → 偶现 "UNSAFE" 被误判为不合规结论
- 修复：`zhiyun_shouhu_agent.py` 新增 `_verdict_unsafe` 静态方法（结论词首尾 token 严格匹配），
  替换 `check_input` 与 `audit` 两处裸 in 判断；追加回归测试 `test_verdict_tolerates_mock_echo`

#### 修复 2：中文语境 `\b` 边界失效致 PII 检测落空

- 现象：`test_pii_input_flagged_medium` 失败（预期 MEDIUM 实得 LOW）
- 根因：Python re Unicode 模式下中文汉字属 `\w`，「手机号是138...」中"是"与"1"之间无 `\b` 边界，
  四条 PII 正则在中文邻接场景全部失明（原型缺陷）
- 修复：`SENSITIVE_PATTERNS` 全部改用 lookaround（`(?<!\d)...(?!\d)` 等），中文邻接可命中

#### 修复 3：Mock 分支丢弃 RAG context

- 现象：`test_context_is_prefixed_to_prompt_in_mock` 失败
- 根因：`BaseAgent.run` 拼接了 `user_content` 但 Mock 分支只回显 `prompt`，与真实调用行为不一致
- 修复：Mock 分支改为 `self._mock_run(user_content)`

#### 工具链修复：venv 双版本混用

- 现象：`.venv/bin/lint-imports` 报 `No module named 'rich'`，但 `python -c "import rich"` 成功
- 根因：`.venv` 曾被 Python 3.14 与 3.12 先后创建，bin/ 下 console 脚本残留 3.14 shebang，
  而 flake8/black/isort/rich 均装在 3.12 site-packages
- 修复：`python -m pip install --force-reinstall --no-deps` 在 3.12 上下文重生成 bin 脚本

#### 门禁调和：black 与 flake8 规则冲突

- orchestrator.py 长 f-string：black 强制收拢单表达式 → 改为两段隐式拼接（black 稳定保留）
- retriever.py Protocol `...` 省略体：black 折叠单行触发 E704 → def 首行 `# noqa: E704`

#### check_doc_links 豁免外部资料
