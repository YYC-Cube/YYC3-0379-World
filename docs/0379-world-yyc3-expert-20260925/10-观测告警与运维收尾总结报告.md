# 📋 观测告警与运维收尾总结报告

## 一、① linger 执行实况（部分达成，唯一待用户项）

| 节点 | 路径尝试 | 结果 |
| ---- | -------- | ---- |
| yyc3-102 直连 | `sudo -n`（免密） | ❌ 需密码（ssh 无 tty 不可交互） |
| 101→102 提权跳板 | sudo101 OK，但 102 root 无互信 | ❌ `root@yyc3-102: Permission denied` |

**结论**：102 linger 无远程提权路径，需**用户在 102 本地终端执行一条**（执行后 `loginctl show-user $USER -p Linger` 应为 `yes`）：

```bash
sudo loginctl enable-linger $USER
```

现态兜底：user 单元 `enabled+active`——**登录会话内自启已生效**；仅「无人登录的开机冷启」依赖 linger。风险敞口评估：DGX 节点重启场景本就需人工到场，可接受。

## 二、② Prometheus heartbeat 告警规则 ✅

[registry-heartbeat.rules.yml](../../deploy/nas/prometheus-rules/registry-heartbeat.rules.yml) 三规则（入库 + 已部署 NAS volume）：

| 规则 | 触发 | 级别 |
| ---- | ---- | ---- |
| `RegistryModelHeartbeatStale` | hb_age>120s 持续 1min（排除 -1 手动模式） | warning（TTL 300s 摘除前预警） |
| `RegistryModelReadyLost` | ready 掉线超 3min 且心跳仍在（排空未收尾） | info |
| `RegistryMetricsGap` | 指标整体 absent 5min（观测面缺口） | warning |

部署链：规则文件入 `yyc3-33_prometheus-conf` volume（/etc/prometheus/）+ prometheus.yml 挂 `rule_files`（幂等追加）+ 热重载 → **三规则加载成功全 inactive**（正常态：五服务心跳新鲜）——容器内 API 实证。

> 持久化注意：volume 内 prometheus.yml 修改为 volume 直写（compose 重建不覆盖 named volume 数据，重启安全）；规则文件同步入库 `deploy/nas/prometheus-rules/`（溯源 + 重建指引）。
