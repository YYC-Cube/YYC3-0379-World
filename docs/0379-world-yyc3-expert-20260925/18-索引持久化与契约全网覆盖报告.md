## 四、🚨 附带：旗舰 TP=2 OOM 下线事故（契约端点首个生产捕获）

- **发现路径**：T2 跨节点验证时 9103 契约如实报 `degraded/upstream 0` → 顺藤定因
- **根因**：昨日 14:52 N2 内存压力 **Ray TP worker rank=1 被 OOM kill** → executor 关闭；时间线正对 N2 拉 8B embedding+reranker 窗口（**UMA 共享内存架构下 RAG 8B 上探对旗舰的连带挤压**）；此后 worker `restarts=99`（13h crash loop）
- **深因（第二轮重启失败）**：head crash-loop 二次重启后 ray actor 句柄跨 session 失配（job 01000000≠02000000）——双机 Ray 重启需 worker/head **协同时序**（worker 先建新 session → head 跟进）
- **处置**：协同重启（worker → head，12:31 CST）；N2 水位复勘 56G 可用（当下无挤压）
- **待办移交**：旗舰恢复确认 + N2 GPU/内存预算表固化（8B×2 常驻与旗舰 TP worker 的 UMA 配额共存策略）——建议下轮专项
