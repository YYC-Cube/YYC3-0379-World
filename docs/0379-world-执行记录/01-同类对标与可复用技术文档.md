### 1.2 各家核心优势提炼（可借鉴点）

#### LiteLLM（企业级标杆）
1. **Virtual Keys 体系**：每把密钥独立预算（`max_budget` + `budget_duration` 滚动窗口 24h/7d/30d 自动重置）、模型白名单、团队归属 → *成本治理核心范式*
2. **Budget Fallbacks**：某模型日预算耗尽 → 静默降级到廉价模型链而非报错
3. **Prompt Cache 自动注入**：`cache_control_injection_points` 自动标注 system 消息，Claude 缓存命中价 ~10%
4. **异步后台记账**：spend/rate-limit 更新全部在响应后异步执行，**DB 写不进请求路径**
5. **请求生命周期分层**：Auth(缓存优先) → RateLimit → Router(fallback→retry→call)

#### One-API / New-API（中转分发标杆）
1. **渠道倍率计费**：不同渠道/模型设置成本倍率，精准核算
2. **多 Key 轮询**：单渠道多 API Key 自动轮换，规避单 Key 限频
3. **故障渠道自动禁用** + 测试通道一键验活
4. **令牌分组**：不同令牌可用不同模型分组与倍率

#### Higress AI（云原生插件化标杆）
1. **Token 级限流**：`token_per_minute/hour/day` 多粒度，按 consumer/header/IP 维度分键（Redis 计数）
2. **语义缓存**：Embedding 相似度命中缓存，跨措辞复用响应
3. **AI 数据脱敏 / 提示注入检测**：请求前后双端 Guardrail
4. **HTTP↔MCP 协议转换**：存量 API 零改造暴露为 MCP 工具

#### Kong AI Gateway（企业治理标杆）
1. **Prompt Template 插件**：管理员预置模板+变量占位符，禁止任意注入
2. **声明式配置 (decK)**：网关配置即代码、GitOps 管理本项目源码仓库内即得

### 1.3 本项目**已领先**同类的差异化优势

| 优势 | 说明 | 同类对比 |
| ---- | ---- | -------- |
| **异构多端推理池** | ECS 边缘 → NAS 网关 → DGX 双机 TP=2 → Mac 数字人线，家庭级设备跑生产级闭环 | 同类多为纯云/纯本地单态 |

## 二、本项目可复用技术资产库

> 以下模式均可**直接抽取复用**到其他 YYC³ 项目或同类网关项目。

### 2.1 上游池注册表模式（⭐ 核心资产）

**来源**: [upstream_registry.py](file:///Users/yanyu/YYC-Cube/YYC3-0379-World/core/api/services/upstream_registry.py)

```jsonc
// env: OPENAI_COMPATIBLE_UPSTREAMS（单行 JSON）
[
  {
    "name": "dgx-tp2",
    "base_url": "http://n1:8001/v1",
    "fallback_url": "http://n2:8001/v1",   // 同上游备用地址
    "models": ["deepseek-v4*"],             // fnmatch 通配
    "capability": "chat",                   // chat/embeddings/rerank/asr
    "api_key_env": "DGX_API_KEY",           // 按名引用 env，不入池
    "priority": 10,                          // 越小越优先
    "weight": 100,
    "capacity": 32
  }
]
```

**可复用要素**:
- **熔断状态机**：`连续 3 败 → OPEN(30s) → HALF_OPEN(单请求探测) → 成功回 CLOSED`
- **解析容错**：JSON 解析失败降级空池仅告警，单条无效跳过，绝不 crash
- **fnmatch 模型匹配** + `serves(model)` 判定
- **EWMA 统计**（α=0.3）内嵌每上游，deque(maxlen=200) 滑窗

### 2.2 ADAPTIVE 动态权重路由模式

**来源**: [model_router.py](file:///Users/yanyu/YYC-Cube/YYC3-0379-World/core/api/services/model_router.py)

```python
# 反馈循环三要素（任何调度系统可复用）
EWMA_ALPHA = 0.3                    # 平滑因子
WEIGHT_UPDATE_INTERVAL = 10.0       # 权重重算周期
recent_records: deque(maxlen=200)   # 每节点滑窗

# 循环: request → record_result(latency/success/tokens) → _update_dynamic_weights()
# 权重 = f(EWMA延迟↓, EWMA错误率↓, 实时负载↓) → 加权随机选择
```

**五策略枚举**可直接移植：`ROUND_ROBIN / WEIGHTED_LATENCY / LEAST_CONNECTIONS / RANDOM / ADAPTIVE`

### 2.3 认证中间件模式

**来源**: [auth.py](file:///Users/yanyu/YYC-Cube/YYC3-0379-World/core/api/middleware/auth.py)

- JWT + `X-API-Key` 双模认证，`AuthConfig` 全部 property 动态读 settings（避免 import 时固化）
- `SKIP_AUTH_PATHS`（精确）+ `SKIP_AUTH_PREFIXES`（前缀）双层白名单
- API Keys 逗号分隔 env 动态解析：`{k.strip() for k in settings.api_keys.split(",") if k.strip()}`

## 三、融合演进路线图（业界优势 × 本项目落地）

> 原则：**吸收范式不引重依赖**——用本项目 FastAPI 栈自研实现，保持轻量可控。

### Phase A：成本治理（对齐 LiteLLM 虚拟密钥）

| 任务 | 实现 | 验收 |
| ---- | ---- | ---- |
| A1 虚拟密钥表 | PG 新表 `virtual_keys(id, key_hash, owner, model_whitelist, monthly_budget_usd, spent_usd, expires_at)`；auth.py 校验链路接入 | 每把 key 可独立禁用/限额/限模型 |
| A2 预算窗口 | `spent_usd` 按请求 usage 累计（token×倍率），滚动 24h/30d 窗口 Redis ZSET 滑窗计数 | 超预算返回 402 + 提示 |
| A3 Budget Fallback | 预算耗尽 → 上游池选同 capability 低价 priority 备选 | 静默降级不报错 |
| A4 异步记账 | FastAPI `BackgroundTasks` 写 spend log，**不阻塞响应**（学 LiteLLM）| P99 增量 <5ms |

### Phase B：Token 级流量治理（对齐 Higress）

| 任务 | 实现 |
| ---- | ---- |
| B1 Token 限流 | rate_limit.py 扩展：响应后按 usage.total_tokens 写 Redis 计数器（per-key，minute/hour/day 三粒度）|
| B2 语义缓存 | pgvector 复用：查询 embedding 相似度 >0.95 直接返回缓存响应（`ai-cache` 范式）|
| B3 多 Key 轮询 | 上游 Upstream 增加 `api_key_envs: [...]` 数组轮换（学 New-API）|

### Phase C：安全护栏（对齐 Higress/Kong）

| 任务 | 实现 |
| ---- | ---- |
| C1 提示注入检测 | utils/filter.py 升级：规则库（越权指令模式）+ 可选本地小模型分类 |
| C2 数据脱敏 | 响应侧正则+NER 遮蔽手机号/身份证/密钥模式 |
| C3 Prompt 模板 | `/v1/templates` 管理端点，`{{var}}` 占位符渲染，禁自由注入（学 Kong）|

### Phase D：运维增强

| 任务 | 实现 |
| ---- | ---- |
| D1 上游池热重载 | `POST /v1/admin/upstreams/reload`（auth 保护）+ 背后 `registry.load_from_env()` |
| D2 熔断状态共享 | Redis 存 breaker_state（`api_workers=4` 收敛为全局一致视图）|
| D3 Grafana 看板扩展 | 现有 `model-usage-stats.json` 增加：虚拟密钥 spend、Token 限流命中、熔断事件时间线 |
| D4 mypy 收敛 | 按 advisory 报告分 3 批转阻塞 |

**优先级建议**: A1→B1→D1 为第一梯队（成本+流量+运维三大刚需闭环），其余按需。
