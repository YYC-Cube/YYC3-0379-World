# Phase 2 异步编排 Worker 化（追加规划，2026-09-26）

## 一、总体目标

`/v1/agent/tasks` 由 BackgroundTasks 骨架升级为「提交-认领-回调」范式：复用 video_tasks
租约机制（Redis FIFO + SET 索引 + lease_until + 过期回收），状态机扩为
queued→running→succeeded/failed，WebSocket 进度推送（/ws/agent），支持内置 Worker 开箱即用

+ 外置 Worker 水平扩展双通道。

## 二、任务分解与验收

| 任务 | 交付物 | 验收标准 | 状态 |
| ---- | ------ | -------- | ---- |
| 编排器进度钩子 | orchestrator.execute(progress_cb) 每步/阶段/blocked 事件 | 不改 steps 审计数组结构；回调异常不阻断编排 | ✅ |
| Worker 化 | core/api/api/agent.py 重写（队列/租约/回收/事件） | 状态机与 video_tasks 范式一致；_MAX_ATTEMPTS=2 | ✅ |
| admin 四端点 | claim / heartbeat / result / failure（ADMIN_API_KEYS 保护） | 外置 Worker 全生命周期可驱动 | ✅ |
| 内置 Worker | start_worker/stop_worker + main.py 生命周期挂载 | 进程内 asyncio 循环；幂等启动；退避容错 | ✅ |
| WS 进度流 | /ws/agent/{task_id}?token=（快照 + 事件流） | 终态即返；空轮询间隙复核终态防悬挂 | ✅ |
| 生命周期接线 | main.py startup/shutdown + .env.example AGENT_WORKER_ENABLED | 默认 true 开箱即用；外置部署置 false | ✅ |
| 测试 | tests/test_agent_api.py 重写（15 integration）+ progress_cb 单测 2 | 全链路/租约回收/admin 门禁/WS 推送全绿 | ✅ |

## 三、关键决策

| 决策 | 原因 |
| ---- | ---- |
| 完整镜像 video_tasks 租约范式 | 已验证的权威蓝本，认知零成本迁移；admin 端点由 AuthMiddleware 自动保护 |
| 双通道（内置 + 外置 Worker） | 默认零部署成本；水平扩展时置 AGENT_WORKER_ENABLED=false 改走 claim 端点 |
| 进度事件走 Redis pub/sub（agent:events:{id}） | 与任务态薄存储层解耦；尽力而为语义（推送失败仅告警不阻断） |
| 编排器 to_thread + run_coroutine_threadsafe 桥 | 同步九步管线不阻塞事件循环；跨线程进度事件安全调度回主循环 |
| WS 终态兜底复核（5 次空轮询后查任务态） | 防「终态事件早于订阅发布」导致订阅者永久悬挂（五高-高可用） |
| 测试经 admin 端点驱动同一状态机 | AGENT_WORKER_ENABLED=false 下用真实代码路径覆盖，仅存储层薄桩替 |

# Phase 2 A2A 协议落地（追加规划，2026-09-26）

## 一、总体目标

90s 超时离线 / 能力标签发现）、标准消息信封、审计流（stream:audit:log 接 zhiyun
set_audit_sink + 编排任务全生命周期审计留痕），为外置业务 Agent Worker 接入打通协议层。

## 二、任务分解与验收

| 任务 | 交付物 | 验收标准 | 状态 |
| ---- | ------ | -------- | ---- |

| 端点 | `core/api/api/a2a.py`（能力发现 + admin 注册/心跳） | GET /v1/a2a/agents?capability= 过滤正确；admin 端点鉴权 | ✅ |
| 审计埋点 | agent.py 任务生命周期 9 处（submit/claim/requeue/sweep_failed/succeeded/failed） | entry 结构对齐 zhiyun write_audit_log（trace_id/auditor/action/detail/timestamp） | ✅ |

| 测试 | tests/test_a2a_protocol.py（21 integration）+ agent 整包审计联动用例 + zhiyun 降级单测 | 全绿 | ✅ |

## 三、关键决策

| 决策 | 原因 |
| ---- | ---- |
| 协议模块放 app/services 层（非 core/agents） | A2A 依赖网关 Redis 设施与配置；core/agents 保持零项目耦合，sink 经可插拔接口注入 |

# Phase 2 业务 Agent 外置 Worker 化（追加规划，2026-09-26）

## 一、总体目标

按可行性报告 Phase 2「A2A Worker 化：业务 Agent 独立进程消费 Redis Stream（先 3 Agent：
语枢/预见/创想）」，兑现上轮预留（消费者组落地时一并开放任务投递）：A2A 任务通道全链路
闭环——提交端点（信封投递）→ 消费者组（XREADGROUP/ACK）→ 失败重试（3 次）→ 死信流（DLQ）
→ 结果回执（stream:agent:result:callback），外置 Worker 以独立进程水平扩展。

## 二、任务分解与验收

| 任务 | 交付物 | 验收标准 | 状态 |
| ---- | ------ | -------- | ---- |
| 协议层消费者组原语 | a2a_protocol.py 追加（ensure_group/send/poll/ack/nack+DLQ 迁移） | 镜像原型 MessageConsumer 语义；nack 达 MAX_RETRY=3 迁移 {stream}:dlq 并 ACK + 审计 | ✅ |
| 任务投递端点 | POST /v1/agent/a2a/tasks（receiver 直投 / capability 在线发现） | 信封完整落 stream:agent:task:{id}；无在线 Agent 404；路由目标缺失 400 | ✅ |
| 业务 Agent 装配 | services/agent_workers.py（handle_task 分发 5 task_type + AgentWorker 运行器） | 语枢 analyze / 预见 forecast·qualitative / 创想 polish·brainstorm；Mock 模式零网络 | ✅ |
| 独立进程入口 | core/scripts/agent_worker.py（--agents / A2A_WORKER_AGENTS / 信号优雅退出） | 外置执行位上报（卡片 endpoint 覆盖）；asyncio.gather 多 Agent 并发 | ✅ |
| 配置声明 | .env.example 追加 A2A_WORKER_AGENTS / A2A_WORKER_CONSUMER | 网关进程不读取；仅 Worker 进程消费清单约束 | ✅ |
| 测试 | tests/test_a2a_worker.py（20 integration：原语 4/分发 7/运行 4/端点+端到端 5） | 消费者组语义内存桩；端到端 submit→consume→result 闭环断言 | ✅ |

## 三、关键决策

| 决策 | 原因 |
| ---- | ---- |
| A2A 任务通道与 P1 编排队列并存互补，不替换 agent:queue | 九步编排任务已有租约闭环（List 范式）；A2A 流通道服务单 Agent 协同任务（协议互操作），语义分层 |
| 消费者组原语走异步客户端（与注册中心同款线程边界） | 独立 Worker 进程 asyncio.run 驱动；测试复用 FakeAsyncRedis 桩范式；代码单一事实源 |
| 任务流按 agent_id 约定路由（stream:agent:task:{id}），不依赖 endpoint 字段 | 约定优于配置；endpoint 仅作能力发现可见性标注 |
| nack 重试计数独立 Key（a2a:retry:{stream_msg_id}，1h TTL） | 镜像原型语义；stream_msg_id 全局唯一免跨流串计数 |
| 结果流 MAXLEN 近似修剪（10k） | 无消费者的回执流防无限堆积；DLQ 深度留给 Grafana 面板告警（后续可观测项） |
| XPENDING/XAUTOCLAIM 挂起回收暂不实现 | 原型亦无；消费者掉线场景由重试计数 + DLQ 兜底，标注后续优化 |

# Phase 2 A2A 结果流消费端（追加规划，2026-09-26）

## 一、总体目标

兑现上轮预留「结果流消费端（编排器聚合 AsyncOrchestrator 结果回执消费）+ XPENDING/XAUTOCLAIM
挂起回收」：网关内嵌消费泵聚合 stream:agent:result:callback 回执（wait_one 请求-响应闭环 /
wait_all 多 Agent 扇入等齐），XAUTOCLAIM 兜底消费者宕机滞留 PEL 的回执，新增同步提交端点
完成 A2A 全链路最后一块闭环（提交 → 消费 → 回执 → 等待应答）。

## 二、任务分解与验收

| 任务 | 交付物 | 验收标准 | 状态 |
| ---- | ------ | -------- | ---- |
| 协议层回收原语 | claim_stale_messages（XAUTOCLAIM，兼容 2/3 元响应）+ RESULT_GROUP 常量 + poll_messages block≤0 非阻塞修正 | Redis BLOCK 0 无限期阻塞语义不被误用；drain 路径零阻塞 | ✅ |
| ResultHub 聚合消费端 | services/a2a_result.py（_TraceAggregate 按 sender 覆盖式聚合 + wait_one/wait_all + run_once/reclaim_once + run_forever + start/stop 生命周期） | 事件驱动零轮询；同 sender 回执重放幂等（进度由集合推导）；孤儿回执 result_orphan 审计 + ACK 不滞留 PEL | ✅ |
| 同步提交端点 | POST /v1/agent/a2a/tasks/sync（注册聚合器 → 投递 → drain 追平在途回执 → wait_one → 终态返回） | 超时返回 timeout（任务不丢仍由 Worker 消费）；调用方可指定 trace_id 关联回执 | ✅ |
| 生命周期接线 | main.py startup/shutdown（A2A_ENABLED × A2A_RESULT_CONSUMER_ENABLED 双控）+ .env.example 声明 | 既有测试（A2A_ENABLED=false）零影响；幂等启动 | ✅ |
| 测试 | tests/test_a2a_result.py（17 integration：往返 2/聚合 6/批量 2/回收 3/同步端点 4） | FakeAsyncRedis v2（PEL 挂起 + 时钟 + XAUTOCLAIM）；等待场景单循环驱动 | ✅ |

## 三、关键决策

| 决策 | 原因 |
| ---- | ---- |
| 先注册聚合器后投递任务 + drain 追平 | 杜绝「回执先于注册」竞态；drain 同时消除预置回执的首响应延迟 |
| 结果按 sender 覆盖式存储，进度由集合推导（原型为计数器） | 原型计数器遇回执重放（XAUTOCLAIM 再投递）会重复计数；集合语义天然幂等 |
| 孤儿回执审计（result_orphan）+ ACK 而非滞留 | 等待者超时离开后回执仍有处可查（Loki 检索）；PEL 清洁防 reclaim 风暴 |
| wait_one/wait_all 事件驱动（asyncio.Event）替代原型 get_task_status 轮询 | 请求-响应语义最短延迟；多 Agent 扇入等齐零轮询开销 |
| 生命周期默认启用但双控（A2A_ENABLED × A2A_RESULT_CONSUMER_ENABLED） | 网关即编排器为默认形态；独立编排器部署时网关侧可关；既有测试 env 已关 A2A_ENABLED 天然隔离 |
| 回收阈值 CLAIM_IDLE_MS=60s / 周期 30s | 远大于正常处理时长（毫秒级）；宕机回执最长 90s 内被回收派发 |

## 三、关键决策

| 决策 | 原因 |
| ---- | ---- |
| Agent 任务/编排 est_cost=0（仅查已花超限） | 协同事务无 token usage 可估；预算闸门语义=「已花超限即拒」 |
| 记账双探针 X-A2A-Cost > X-Total-Cost + 兜底常量 0.001 USD | 兼容端点未来直报成本；兜底防长期 0 计量掩盖 vk 用量 |
| 中间件记账 `await enqueue_spend`（不经 create_task） | 后台任务在响应返回后可能被事件循环丢弃 → 记账丢失；LPUSH 微秒级直 await 保证落队列后再响应 |
| `_authenticate` api_key 分支提取 `_authenticate_vk_or_static` 类方法 | 测试双保险打桩：vk 明文与 conftest 静态 API_KEYS 不同源，authenticate 返回 None 会降级命中静态键误判静态身份 |
| 编排端点超时返回 status=timeout + 部分 results | 扇出不回滚已投递任务（Worker 正常消费，结果不丢）；调用方可观部分聚合进度 |
| PEL 统计用 XAUTOCLAIM dryrun（min_idle_ms=0） | 只读统计不改消息归属；避免 XPENDING 逐条解析开销 |
| Gauge 只采 A2A_WORKER_AGENTS 声明的流 | 无 Worker 消费的死流不产生假告警 |
